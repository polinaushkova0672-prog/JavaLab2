# Лабораторная работа 2 — Мышь в лабиринте

Оконное приложение на **Java 21, Swing, Maven**. Выполняемые зависимости не требуются.

## Сборка и запуск

Установите JDK 21 и Maven, укажите JDK 21 в `JAVA_HOME`.

```shell
mvn test
mvn package
java -jar target/OOPLaba2-1.0-SNAPSHOT.jar
```

В IntelliJ IDEA выберите Project SDK 21, загрузите Maven-проект и запустите `org.example.Main`.
Графический тест требует рабочего стола; на сервере без дисплея запускайте `mvn test -Dtest=MazeTest`.

## Использование

1. Укажите строки и столбцы (2–200), нажмите «Сгенерировать». Генератор DFS с возвратом гарантирует путь до сыра. Мышь начинает в нижнем левом углу, сыр находится в верхнем правом. «Пустое поле» создаёт основу для своей схемы с теми же позициями старта и сыра.
2. При включённом редактировании выберите тип клетки и нажмите на поле. Чтобы убрать старый старт или сыр, сначала перенесите его соответствующим инструментом. Стены могут сделать сыр недостижимым; программа обнаружит это перед обучением.
3. Задайте Z > x > 0 и y > 0, нажмите «Применить награды». Изменение схемы или наград сбрасывает обучение.
4. Отключите редактирование для ручного движения кнопками или стрелками клавиатуры. Элементы ввода могут перехватывать стрелки; кнопки направления доступны всегда.
5. Нажмите «Обучить», затем «Показать маршрут». «Стоп» прерывает обучение или анимацию. «На старт» сбрасывает попытку, сохраняя обученную таблицу.

Цвета: серый — стена, голубой + — вода (после питья ·), красный — электричество, зелёный S — старт, жёлтый C — сыр, фиолетовый — мышь. Поле прокручивается и масштабируется.

## Правила и принятые решения

Сыр даёт +Z и завершает попытку; вода даёт +x при первом посещении за попытку; электричество даёт −y при каждом входе. Пустая клетка стоит −1, столкновение со стеной или границей −3. Специальная награда заменяет штраф шага. Сумма отображается после каждого действия, журнал содержит последние 100 действий. В новой попытке вода восстанавливается.

Задание не задаёт частоту питья или жажду: питьё учитывается при посещении воды, обязательный интервал не вводится. Вода одноразовая в рамках попытки, чтобы исключить бесконечное накопление награды на одной клетке.

## Алгоритмы из презентации

Генерация использует DFS с возвратом (слайды 11–12 файла «Лаб 2 - ООП на Java.pdf»): поле заполняется стенами, стартовая вершина помечается посещённой, затем выбирается случайный непосещённый сосед и прорезается проход. Если таких соседей нет, алгоритм возвращается к предыдущей вершине. Работа заканчивается после обхода всех вершин. Между вершинами оставляется клетка стены; для чётных размеров сыр соединяется с ближайшим коридором. Стек хранится явно, без рекурсии. Все проходы связаны, циклов нет. Вода и ловушки размещаются после создания коридоров. Проверка достижимости также выполняется поиском в глубину.

Q-learning использует формулу Беллмана со слайдов 9–10:

```text
Q(s,a) ← Q(s,a) + α × [reward + γ × max Q(s′,a′) − Q(s,a)]
```

При достижении сыра будущая награда равна нулю. α=0.25, γ=0.95; исследование постепенно уменьшается с 0.9 до 0.05. Координаты мыши определяют её положение (слайд 8). Для сохранённого правила одноразовой воды состояние дополнительно включает множество выпитых клеток: это необходимо, поскольку награда той же клетки меняется после питья. Обучение выполняется небольшими пакетами на EDT, поэтому окно реагирует на «Стоп». Каждое новое обучение начинается с пустой таблицы. Лимит попытки — min(10000, строки × столбцы × 10), лимит таблицы — 100000 состояний. Обучение вероятностное, успешный маршрут для произвольной пользовательской схемы за заданное число попыток не гарантируется; при большом числе клеток воды пространство состояний растёт быстро.

Размер модели произвольный прямоугольный от 2×2; окно ограничивает ввод 200×200 для разумного расхода памяти.

## ООП

- `Maze` инкапсулирует схему, редактирование и проверку связности.
- `Environment` рассчитывает обратную связь и статистику попытки.
- `QLearningAgent` хранит стратегию и обновляет её по подкреплению.
- `MazePanel` рисует поле; `MazeFrame` связывает модель и интерфейс.
- `Position`, `Rewards`, `Transition` — неизменяемые объекты данных; `CellType` и `Direction` — перечисления.

## Проверки

JUnit проверяет генерацию на разных размерах и случайных seed, связность и отсутствие циклов у DFS-коридоров (включая 200×200), расположение старта и сыра, точный расчёт формулы Беллмана, достижимость, перенос маркеров, валидацию, стены и границы, одноразовую воду и сброс, штрафы, завершение и сумму, а также обучение на контрольной схеме. GUI-тест создаёт окно, вызывает основные кнопки, рисует его в изображение и проверяет завершение обучения.
